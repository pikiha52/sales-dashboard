## Goal

Sales team runs a small local web app on sales.csv (Sep–Oct 2026). It shows sales by region and brand, flags the 5 weakest outlets, and produces a one-paragraph summary that a bot sends automatically to the sales manager on Telegram.

## Requirements Summary

Requirements were provided directly:
- Sales per region and per brand
- 5 weakest outlets flagged
- One-paragraph summary readable on Telegram
- Summary sent automatically by a Telegram bot
- Runs on the customer's own computer, delivered as zip + README

## Architecture & API Contracts

No new HTTP API. Three pieces share one logic file:
- `report.js`: `parseCSV`, `buildReport`, `summaryText`. Plain JS that runs both in the browser (global functions) and in Node (`module.exports`).
- `index.html`: static dashboard. Opened directly from disk (file picker); auto-loads `sales.csv` when served over HTTP.
- `send.js`: Node CLI that calls the Telegram Bot API `POST https://api.telegram.org/bot<token>/sendMessage` once per chat ID. It has a 15 s timeout and exits 1 on any failure.

Scheduling uses the OS (Windows Task Scheduler / cron), not app code.

## Key Decisions & Architectural Notes

- Metric is `net_sales_idr`; returns (negative rows) reduce net.
- "Weakest outlet" means the lowest total net sales in the file period. The dashboard shows month split, change, invoice count and last order date so a manager can judge context (for example, small outlet type).
- Region spelling is unified case-insensitively, plus an alias map (`Jabar` → Jawa Barat). The canonical spelling is the most frequent raw spelling.
- Exact duplicate rows are dropped and reported.
- The bot token lives only in `.env` / environment, never in the browser. That is why sending is a CLI and not a dashboard button.
- No dependencies: no npm, no chart library. Bars and the heatmap are CSS.

## Constraints Discovered

- Data issues in sample: 3 exact duplicates, 10 region spellings, 1 return, 5 missing salesman, trailing spaces in outlet names.
- Node 20.11 lacks `process.loadEnvFile`, so `send.js` has a 6-line `.env` reader.

## Iteration 2 — Telegram message: formatted + interactive (2026-11-23)

- The message is now HTML-formatted (`parse_mode: HTML`): sections for totals, region, brand and the 5 weakest outlets, with all CSV text HTML-escaped.
- It has an inline keyboard with 4 views: Ringkasan, Region, Brand and Outlet lemah. A button press edits the same message in place, and the active view is marked with `•`.
- `node send.js --listen` runs a long-polling bot (getUpdates, no webhook or server). It answers button presses and the `/ringkasan` command.
- Security: only chat IDs listed in `TELEGRAM_CHAT_ID` receive sales data. Unknown chats get only their own chat ID.
- Tests: 7/7 green. Two were added: view formatting and escaping, and the bot handler, including that no data leaks to an unknown chat.
